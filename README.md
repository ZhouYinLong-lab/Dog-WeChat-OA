# 微信公众号富文本往返编辑器

一个用于验证和实现“微信公众号编辑器 -> 本工具 -> 微信公众号编辑器”富文本往返的单页 MVP。

## 结论

[TwiShimmer 的调查](https://gist.github.com/TwiShimmer/149ec106347162aaae1208ab23435357)与本项目的核心技术路线基本一致：公众号正文以 HTML Fragment、行内 CSS 和微信属性为主要交换格式；浏览器通过剪贴板的 `text/html` 导入和导出；编辑区采用隔离的 `iframe + contenteditable`，避免把原始 DOM 转成 Markdown 或受限编辑器 Schema。

调查中的以下说法需要收窄：

- “一模一样”应定义为未修改区域视觉一致，而不是 HTML 字符串逐字一致。微信会过滤并重新序列化内容。
- 普通文本、图片、列表、表格和行内样式适合做往返；视频、音频、投票、小程序等微信插件卡片不能承诺通过剪贴板无损往返。
- 微信复制出的 HTML 不能一概视为无需处理。工具仍需移除脚本、事件属性和危险 URL，同时保留一份未清洗的原始 HTML 用于调查。
- Gist 对 UEditor/ProseMirror 混合架构的判断可作为实现线索，但在没有可复现源码位置、版本和抓包样本时，不应视为稳定接口契约。

## 已实现

- 捕获并展示 `text/html`、`text/plain` 和原始 HTML。
- 统计标签、行内样式、图片和可操作节点。
- 使用接近公众号正文的基础 CSS 进行手机宽度预览。
- 原生 DOM 手动编辑、撤销/重做和常用格式工具。
- 为 DOM 节点分配临时 ID，让 LLM 只返回受限 JSON 操作。
- 导出前移除内部属性，并写入 HTML/纯文本双格式剪贴板。
- 检查 `div` 标准化、非微信媒体、插件卡片、背景图和本地图片等风险。

## 运行

项目是纯静态页面。为启用剪贴板 API，请通过 localhost 或 HTTPS 打开：

```powershell
python -m http.server 8765
```

访问 `http://localhost:8765/`。

## 真机验收

仓库中的静态检查只能验证格式约定，最终兼容性必须在已登录的微信公众号后台完成：

1. 分别准备普通段落、复杂 `section` 卡片、列表、表格、引用、代码块和图片样本。
2. 从公众号编辑器复制到本工具，不修改后复制回公众号。
3. 对比文字、图片、字号、颜色、间距和布局，并保存原始 HTML 与截图。
4. 对手动修改和 LLM 节点级修改重复测试。

当前 MVP 不承诺微信插件卡片、本地新增图片和第三方外链图片的无损往返。
